# PL-0001 · 이상 탐지 데이터셋 생성 시 recipe 목적 저장 불일치

## 해결

`WpfDatasetSetupExecutionService`가 처음 저장한 목적은 올바랐지만, recipe 전환 직후 남아 있던 WPF 선택 이벤트가 새 `CData`의 목적을 다시 덮을 수 있었다. 데이터셋 생성 경로만 바인딩 정착 후 canonical 목적을 다시 확인하고 현재 recipe에 최종 저장하도록 변경했다. 일반 도구 전환에서 사용하는 비영속 동기화 경로는 유지했다.

## 완료 증거

- 기본 `--exe-yolov8-anomaly-restart-smoke`가 `--preconfigured-recipe` 없이 통과했다.
- 생성 직후 [manifest](../../artifacts/exe-yolov8-anomaly-restart-smoke/codex_yolov8_anomaly_restart_20260726_170631/screenshots/01c_dataset_manifest_after_create.json)와 [VISION.xml](../../artifacts/exe-yolov8-anomaly-restart-smoke/codex_yolov8_anomaly_restart_20260726_170631/saved-before-restart-VISION.xml)이 모두 `AnomalyDetection`을 기록했다.
- [실행 요약](../../artifacts/exe-yolov8-anomaly-restart-smoke/codex_yolov8_anomaly_restart_20260726_170631/summary.txt)은 재시작 후 후보 1개와 `Abnormal` 상태를 기록했다.
- [현재 EXE 화면](../../artifacts/exe-yolov8-anomaly-restart-smoke/codex_yolov8_anomaly_restart_20260726_170631/screenshots/04_first_abnormal_inference_after_restart.png)에서 전체 이미지 분류 후보와 NG 판정을 확인했다.

## 경계

이 해결은 데이터셋 생성 직후 목적 영속화와 재시작 복원을 증명한다. 분류 모델의 일반화 정확도나 현장 데이터 품질을 증명하지 않는다.
